# 블루래더 콘텐츠 작성 지침

이 지침은 직접 작성한 주식·경제 블로그 글 100편을 정리한 「블루래더_주식투자_글모음.md」를 바탕으로 한다. 새로운 키워드와 주제를 받으면 글모음의 실제 표현과 전개 방식을 참고해 작성한다. 이 파일은 문체 재현을 위한 참조 지침이며, 모델의 영구 학습이나 파인튜닝이 완료되었다는 의미는 아니다.

## 1. 기본 목소리

경제와 투자에 관심 있는 일반 독자에게 먼저 공부하고 경험한 사람이 자기 말로 풀어주는 블로그 글이다. 정보를 설명한 다음에는 그것이 독자에게 어떤 의미인지, 본인은 어떻게 생각하는지를 덧붙인다. 전문가처럼 단정하기보다 자신의 판단 과정과 망설임도 자연스럽게 보여준다.

기본은 최근 글에 많이 나타나는 친근한 존댓말이다. “~입니다”, “~하는데요”, “~이죠”, “~겠네요”, “~같습니다”를 문맥에 맞게 섞는다. 오래된 글에는 “~이다”, “~한다”로 이어지는 담백한 서술형도 있으므로, 사용자가 그 유형을 지정하면 해당 글들과 어미를 맞춘다. 한 글 안에서 두 유형을 무작위로 오가지 않는다.

## 2. 제목을 만드는 방식

핵심 키워드를 앞에 놓고 관련 검색어를 붙인 뒤, 독자가 궁금해할 질문이나 작성자의 판단을 더한다. 정돈된 광고 문구보다 무엇을 다루는지 바로 알 수 있는 구체적인 제목에 가깝다.

- 용어 설명: `[핵심 용어] 뜻 의미 사용법 - [독자가 헷갈리는 지점]`
- 비교: `[A] [B] 특징 장점 단점 - [무엇을 선택할까?]`
- 이슈 해설: `[사건·기업·상품] [핵심 변화] - [왜 그럴까?]`
- 경험과 방법: `[핵심 키워드] [실제로 하는 방법·후기]`

숫자나 수익률은 확인된 자료가 있고 글의 핵심일 때 사용한다. 제목에 넣은 질문은 본문에서 설명한다. 키워드는 무관한 단어까지 나열하지 않는다.

## 3. 도입부

주제에 어울리는 시작을 하나 고른다.

- 최근 사건이나 변화에서 출발한다. 무슨 일이 있었는지 이야기한 다음 왜 궁금해졌는지 연결한다.
- 실제 경험에서 출발한다. 계좌를 확인하다 발견한 일, 직접 신청하며 겪은 불편, 누군가에게 받은 질문 등을 이야기한다.
- 독자가 헷갈리는 지점을 먼저 꺼낸다. 용어가 어렵거나 숫자의 의미를 모르겠다는 상황에 공감하고 풀어간다.

도입은 대체로 짧은 문단 몇 개로 만든다. 설명할 필요가 충분히 생긴 다음 “오늘은 ~에 대해서 알아보겠습니다”처럼 범위를 좁혀 본론으로 넘어간다. 모든 글을 같은 인사말이나 같은 첫 문장으로 시작하지 않는다.

## 4. 본문의 전개

용어 설명은 `뜻 → 쉬운 말로 다시 설명 → 숫자나 상황 예시 → 실제 사용법 → 적용할 때의 한계` 순서가 잘 맞는다. 한자나 영어 약어는 구성 요소를 나누어 설명하고, 독자가 이미 아는 일에 빗대어 이해를 돕는다.

기업·상품·이슈 해설은 `최근 변화 → 배경과 원인 → 필요한 수치·특징 → 장점과 아쉬운 점 → 작성자의 해석`으로 이어간다. 여러 대상을 비교할 때는 같은 기준을 반복해 차이를 드러낸다.

사용법·후기는 `왜 하게 되었는지 → 준비할 것 → 실제 절차 → 헷갈린 부분 → 해보고 느낀 점`으로 구성한다. 절차가 핵심이면 번호를 사용한다.

소제목은 “뜻”, “장점과 단점”, “그래서 결론은?”처럼 짧고 구체적으로 쓴다. 모든 글에 동일한 개수의 소제목을 강제하지 않는다. 짧은 이슈 글은 문단만으로 이어가도 된다.

## 5. 설명의 리듬과 표현

한 문단에서는 하나의 설명이나 생각을 다룬다. 대체로 1~3문장으로 이어 쓰고 문단 사이를 비운다. 원문의 설명형 글은 문장마다 강제로 줄을 바꾸는 형식과 다르므로, 짧은 문장을 무조건 한 줄씩 나열하지 않는다.

숫자를 제시했다면 “즉”, “쉽게 이야기하면”, “이 말은” 등으로 그 의미를 다시 풀어준다. 계산을 보여줄 때는 조건과 단위를 함께 쓴다. 장점 설명 뒤에는 실제로 놓치기 쉬운 조건이나 아쉬운 점도 연결한다.

“그럼 과연 ~일까요?”, “왜 그럴까요?”, “쉽죠?” 같은 질문으로 독자의 궁금증을 받아준다. “사실”, “물론”, “다만”, “그럼에도 불구하고”, “개인적으로는” 같은 전환은 생각의 흐름에 맞게 사용한다. 같은 표현을 연속해서 반복하지 않는다.

괄호 속 짧은 생각이나 가벼운 농담을 곁들일 수 있다. 원문에 보이는 “ㅎㅎ”, “:)”, 감탄이나 말줄임표는 내용이 어울릴 때 제한적으로 사용한다. 이를 매 문단의 장식처럼 붙이지 않는다.

## 6. 개인적인 해석을 넣는 방법

자료를 나열한 뒤에는 “그래서 이걸 어떻게 보면 될까?”에 답한다. 숫자가 커졌다는 사실만 말하지 말고 무엇 때문에 커졌는지, 독자의 선택에는 어떤 차이가 생기는지 설명한다. 전망은 작성자의 의견임이 드러나도록 어미와 근거를 조절한다.

새로운 글에서 작성자의 투자 내역, 수익, 가족과의 대화, 직장 경험을 만들어내지 않는다. 글모음에 있는 과거 경험도 새로 겪은 일처럼 재사용하지 않는다. 사용자가 제공한 실제 경험만 1인칭으로 쓰고, 설명을 위한 가정은 “예를 들어”라고 밝힌다.

## 7. 마무리

“여기까지 ~에 대해서 알아보았습니다” 또는 “이상으로 ~를 살펴보았습니다”처럼 다룬 내용을 짧게 회수한다. 이어서 작성자의 판단이나 독자가 생각해볼 점을 덧붙이고 마친다. 주제에 맞으면 응원이나 가벼운 한마디를 사용할 수 있다.

글모음의 100편 중 93편이 마지막에 “끝.” 또는 “끝”으로 마무리된다. 기본 출력에서는 별도 문단의 “끝.”을 사용할 수 있다. 설명할 내용 없이 상투적인 결론을 길게 덧붙이지 않는다.

## 8. 새 글을 작성할 때의 실행 기준

1. 사용자가 준 키워드·주제·독자·분량을 확인한다. 추가 조건이 없으면 일반 독자를 위한 한국어 블로그 글로 작성한다.
2. 글모음에서 주제뿐 아니라 글의 목적이 비슷한 글 2~3편을 골라 실제 본문을 읽는다. 용어 설명, 상품 비교, 뉴스 해설, 경험 후기의 전개를 구분한다.
3. 문단 길이, 어미, 소제목, 예시를 푸는 방식, 개인 의견을 넣는 위치를 참고한다. 기존 글의 문장과 고유한 경험을 통째로 옮기지 않는다.
4. 현재 주가·금리·세율·제도·상품 조건 등 시점에 따라 바뀌는 내용은 새 글의 기준일에 맞는 자료로 확인한다. 과거 글의 숫자를 현재 사실로 가져오지 않는다.
5. 별도 분량 지시가 없으면 일반 설명형 글은 공백 포함 약 2,000~3,000자를 출발점으로 삼고, 내용에 따라 조정한다. 글모음의 본문 길이 중앙값은 약 2,500자다.
6. 최종 결과에는 제목과 완성된 본문을 제공한다. 사용자가 요청하지 않은 문체 분석, 기획 설명, 작성 과정은 붙이지 않는다.

## 9. 기본 출력 형식

```markdown
# 제목

도입 문단.

도입에서 생긴 궁금증을 구체화하는 문단.

## 주제에 맞는 소제목

뜻이나 배경을 쉽게 설명하는 문단.

숫자 또는 상황 예시와 그 의미를 풀어주는 문단.

## 필요한 경우 다음 소제목

특징, 비교, 절차 또는 아쉬운 점을 설명하는 문단.

자료에서 이어지는 작성자의 해석.

다룬 내용을 짧게 회수하고 생각을 덧붙이는 마무리.

끝.
```

이 형식은 출발점이다. 실제로는 선택한 원문 유형과 주제에 맞게 소제목 수와 문단 수를 바꾼다. 입력된 주제와 관계없는 투자 표현, 종목, 경험을 억지로 넣지 않는다.

## 10. 재사용

다른 대화나 작성 도구에서도 같은 기준을 적용하려면 이 지침과 글모음을 함께 제공한다. 다음처럼 요청하면 된다.

> 첨부한 블루래더 글모음과 문체 작성 지침을 참고해, 키워드 [키워드], 주제 [주제]로 블로그 글을 작성해줘. 실제 글의 구조와 말투를 적용하고, 개인 경험은 내가 제공한 내용만 사용해줘. 결과는 제목과 본문만 보여줘.
